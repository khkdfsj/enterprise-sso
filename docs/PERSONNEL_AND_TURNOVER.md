# 人员管理与换届

## 数据模型

- `people`：永久人员主体，不因换届重建。
- `accounts`：登录账号及启停状态。
- `organization_terms`：届次草稿、计划和生效状态。
- `appointments`：人员在某届的部门、职务和有效期。
- `system_role_assignments`：超级管理员等系统管理权限。
- `application_access_rules`：应用准入规则。

人员姓名、部门和职务可以变化，`people.id` 始终不变。

## 推荐换届流程

1. 超级管理员创建下一届草稿。
2. 在草稿中导入或维护新一届人员、部门和职务。
3. 系统检查重复主职、缺失人员、无效部门和时间冲突。
4. 管理员预览新旧差异并指定生效时间。
5. 由有权管理员发布。
6. 到达生效时间后，在一个数据库事务中结束旧任职、启用新任职并递增权限版本。

不建议每年先暂停所有账号。暂停账号会让普通成员和仍需工作的负责人同时无法登录。更稳妥的做法是：账号身份长期存在，任职和应用权限按届次原子切换；确需冻结时使用明确的维护窗口。

## 当前实现状态

数据库模型、任职状态、权限版本以及原子发布服务已经实现，并有换届端到端测试。人员批量导入、差异预览、审批页面和定时任务管理界面尚未实现；在这些管理工具完成前，不应通过手工 SQL 操作生产库。
