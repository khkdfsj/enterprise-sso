# 人员管理与换届

## 核心原则

`people.id` 完整使用企业微信 UserID；本企业内就是学号。姓名、年级、部门和职位可以变化，UserID 不变。人员主体、登录账号、历届任职和系统管理权限分别保存，历史届次不会因为下一次换届被覆盖。

当前数据基线：

- `2023*`：部长；
- `2024*`：副部长；
- `2025*`：委员；
- `2023195077`、`2007510002`、`88487016` 保留永久有效属性；永久属性与部长、老师、超级管理员职位互不替代。

数据库只保存 Argon2id 密码哈希。新委员和管理员重置后的初始密码是 UserID 后六位，同时写入“需要改密”标记；首次登录强制改密页面仍是后续优化项。

## 人员与账号页面

入口：`/admin/people`。

页面按数据表格展示，不在一行平铺复杂表单：

1. 默认显示当前生效届次；可切换任一历史届次。
2. 可按年级筛选名单。
3. 状态、账号状态、永久属性全部显示中文。
4. 普通委员只能查看名单；副部长及以上可以新增、编辑和重置密码；部长及以上可以移除普通人员。平台管理员不受部门职位限制。
5. 编辑在独立二级页面完成，可同时修改姓名、年级、人员状态、该届部门和职位。
6. 移除使用独立确认页；永久用户和当前登录账号不能移除。移除是软删除：人员历史及审计仍保留。
7. 老师、永久账户和平台管理员可以在独立的“平台身份”页面授予他人平台管理员身份或永久账户属性。
8. 已建届次可直接批量追加委员；整批校验后一次写入，避免只导入半批数据。

## 五步换届流程

入口：`/admin/terms`。同一时间只允许存在一个未完成草稿。

### 第一步：确定届次

选择当前生效届次，填写目标届次、新委员年级和生效时间。保存后立即建立数据库草稿，页面关闭也不会丢失。

### 第二步：选择留任

表格只列出上一届普通人员。勾选需要留任的人；未勾选者在发布时自动卸任并暂停账号。永久用户不出现在选择表中，由系统自动沿用。

### 第三步：调整职位

系统先自动晋升：

- 委员 → 副部长；
- 副部长 → 部长；
- 其他职位默认保持原职位。

页面只显示第二步选中的人员。管理员可逐人修改新部门、新职位，或取消其留任。

### 第四步：新增委员

支持单人录入和批量文本导入。批量格式每行一人：

```text
学号,姓名,部门名称
2026123456,张三,运行部
```

也可使用中文逗号或 Tab 分隔。新人员统一以目标年级入库，职位默认为委员，初始密码为学号后六位。

### 第五步：核对发布

最终表格列出所有普通留任人员和新委员。发布在事务中完成：创建新账号与任职、沿用永久用户、结束旧任职、卸任未入选人员、切换届次并递增授权版本。未来生效的届次只先标记为待生效，不会提前停掉现届账号；到达生效时间后再原子切换。

## 断点续办和返回上一步

每个步骤都写入 `turnover_workflows` 和 `turnover_workflow_members`。管理员可在任意步骤离开；再次进入“届次换届”会看到“继续未完成换届”，并回到上次保存步骤。返回上一步只改变当前查看步骤，不删除已保存名单；重新提交留任名单时，第三步的自动晋升结果会按新选择重新生成。

## 权限和审计

- 平台身份和部门职务分开保存。`super_admin` 表示平台管理员，直接拥有全部后台权限；部长不会自动成为平台管理员。
- 普通委员只读名单；副部长及以上、老师、永久账户和人员管理员可维护人员和办理换届；移除人员要求部长及以上或更高权限。
- 运行部成员可查看接入服务；修改和删除服务只允许创建者本人或平台管理员。
- 老师、永久账户和平台管理员可授予他人平台管理员身份及永久账户属性，操作写入审计日志。
- 永久用户不会被自动卸任或暂停。
- 创建、修改、重置密码、移除、创建换届和发布换届均写入审计日志。
- UserID 是所有接入应用收到的 `sub`，业务系统不得另建可冲突的身份主键。

## 验收覆盖

自动化测试覆盖五步草稿、两级自动晋升、未留任卸任、永久用户沿用、新委员后六位初始密码及改密标记、立即发布、预约生效和旧原子换届回归。生产操作仍应先在草稿中核对名单，再执行最终发布。
