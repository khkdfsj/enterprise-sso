# ESSO-DFSJ（Enterprise SSO）系统总说明

## 1. 系统用途

ESSO 是 Enterprise Single Sign-On 的简称。它是企业内部统一身份认证中心；`ESSO-DFSJ` 同时是生成式接入包的固定目录名。所有受管应用共用一个登录页面，支持账号密码和企业微信扫码。用户在有效会话期内访问其他已授权应用时不必重复输入密码。

旧 `WeComVerificationSystem`、`DepartmentIFO` 及其他服务器程序不属于本项目。本系统使用平行代码、独立服务、独立端口和独立数据库。

## 2. 当前入口

- 认证地址：`http://210.47.163.114/enterprise-sso`
- Discovery：`http://210.47.163.114/enterprise-sso/.well-known/openid-configuration`
- 企业微信手机回调：`https://syauinfo.syau.edu.cn/qywx/enterprise-sso/callback.php`

普通网页在内网使用 IP 80；微信和企业微信扫码只复用原系统已配置的可信域名，新系统使用独立目录和回调文件，不依赖旧扫码系统代码。该域名只面向微信环境，不能用普通浏览器的访问结果判断扫码链路是否可用。

## 3. 登录体验

1. 用户访问已经接入的业务系统。
2. 业务系统发现未登录，自动跳转统一认证中心。
3. 用户使用密码或企业微信扫码。
4. 认证中心重新检查人员、账号、应用和准入规则。
5. 用户返回原业务页面。
6. 有效 SSO 会话内访问其他获授权应用通常无需再次输入密码。

当前会话策略：闲置 2 小时失效，绝对最长 8 小时。应用禁用、账号停用或授权变化后，已有会话不能绕过检查。

## 4. 应用怎样接入

管理员在“新增接入服务”中只填写应用名称和浏览器可访问的项目根地址。系统自动登记精确登录回调、注销返回、健康检查和两项验收地址，并生成一次性的 `ESSO-DFSJ.zip`。接入者把完整文件夹放入项目根目录且禁止更名，不需要逐个复制 SDK 文件或手工填写 Client Secret。

获得专用 Agent 凭据的 AI 也可以按 [Agent 自动接入规范](AGENT_INTEGRATION.md) 调用无图形 API。Agent 必须提供与凭据绑定的稳定身份标记和幂等请求编号；接口登记服务、生成同一个标准包、启动监控并报告连通/登录/注销三项验收状态。Agent API 不会远程改写业务服务器，也不会把生产凭据写入公开 Skill。

PHP 7.4 应用在受保护页面第一行引入：

```php
require_once __DIR__ . '/ESSO-DFSJ/login.php';
$userId = $ssoUser['sub'];
```

退出链接使用 `login.php` 提供的 `$essoLogoutUrl`。部署后必须完成健康连通、真实登录和真实注销三项验收；全部通过后可删除 `test-login.php`、`test-logout.php`，保留 `health.php` 持续监控。登录页面、扫码页面、密码校验、OIDC 令牌签发均由认证中心负责。

## 5. 人员和换届

人员主体长期保留，姓名、年级、部门和职务不作为永久主键。人员页面可按届次和年级查看当前或历史组织，用独立页面完成新增、编辑、密码重置和软删除。

换届使用五步可续办向导：确定届次、选择留任、自动晋升并调整职位、新增委员、核对发布。委员自动升副部长，副部长自动升部长；未留任普通人员在生效时卸任，永久用户自动沿用。每一步落库，可中途离开并从上次步骤继续，也可返回上一步。旧任职结束、新任职启用、账号状态和权限版本在同一事务切换。

## 6. 当前管理能力

- OIDC/PKCE 和 ES256；

- 人员、届次、任职和原子发布模型；
- 网页应用登记、回调地址管理、密钥轮换和准入规则；
- 按届次/年级筛选的人员数据表格、部长以上人员管理、五步可续办换届、登录审计和接入指南；
- 超级管理员初始化、批量迁移和应急维护 CLI；
- 一次性 `ESSO-DFSJ.zip` PHP 7.4 接入包、固定目录调用和三项自动验收；
- 审计基础数据结构与自动化测试。

继续优化项：首次登录强制改密页面、Excel 文件导入、更细的多级审批、审计条件筛选和导出。当前换届已支持页面内批量文本导入。

## 7. 部署隔离

114 只新增 `/enterprise-sso/` 精确子路径 include 和 127.0.0.1:13000 隧道；118 认证服务只监听 127.0.0.1:3000。其他业务路径、监听端口和 HTTPS 策略不变。

系统明确禁止 HSTS，因为同一 IP 仍有其他 HTTP 程序。普通访问只使用校园网可达的 IP 80；既有域名 HTTPS 仅承接企业微信手机回调。

## 8. 数据库决定

当前使用 SQLite WAL，适合单认证节点和当前企业规模。118 原 MariaDB 5.5 承载多套旧业务、有持续外部连接和历史表损坏记录，不能为了本系统直接升级或复用。未来若出现多节点、高并发写入或数据库高可用需求，应建设独立的新数据库实例，不替换旧 MariaDB。

## 9. 更新和 GitHub

GitHub 是唯一源码基线。以后所有更新必须先修改仓库、更新手册、运行测试、提交并推送，再从明确的 commit/tag 发布。生产服务器不得存在长期未回推的手工修改。

涉及数据库结构或大规模数据变更的生产发布必须：

1. 建立一个明确的数据库和配置回滚点；普通样式、文档及可回滚代码发布不重复备份数据库；
2. 建立新的 release 目录；
3. 原子切换 `current`；
4. 只重启本项目服务；
5. 验证健康检查、Discovery、真实登录和应用禁用；
6. 记录生产对应的 commit/tag 和回滚点。
