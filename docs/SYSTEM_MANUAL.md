# Enterprise SSO 系统总说明

## 1. 系统用途

Enterprise SSO 是企业内部统一身份认证中心。所有受管应用共用一个登录页面，支持账号密码和企业微信扫码。用户在有效会话期内访问其他已授权应用时不必重复输入密码。

旧 `WeComVerificationSystem`、`DepartmentIFO` 及其他服务器程序不属于本项目。本系统使用平行代码、独立服务、独立端口和独立数据库。

## 2. 当前入口

- 认证地址：`http://210.47.163.114/enterprise-sso`
- Discovery：`http://210.47.163.114/enterprise-sso/.well-known/openid-configuration`
- 企业微信手机回调：`https://syauinfo.syau.edu.cn/qywx/WeComVerificationSystem/enterprise-sso-callback.php`

普通访问在内网使用 IP，不依赖公网域名或额外证书；既有域名仅供企业微信 OAuth 手机回调使用。

## 3. 登录体验

1. 用户访问已经接入的业务系统。
2. 业务系统发现未登录，自动跳转统一认证中心。
3. 用户使用密码或企业微信扫码。
4. 认证中心重新检查人员、账号、应用和准入规则。
5. 用户返回原业务页面。
6. 有效 SSO 会话内访问其他获授权应用通常无需再次输入密码。

当前会话策略：闲置 2 小时失效，绝对最长 8 小时。应用禁用、账号停用或授权变化后，已有会话不能绕过检查。

## 4. 应用怎样接入

管理员先登记应用名称和精确 HTTPS 回调地址，取得 `client_id` 和一次性显示的 `client_secret`。应用使用 OIDC Authorization Code + PKCE，不自行收集统一认证密码。

PHP 7.4 应用可复制 `sdk/php74`，填写配置并在受保护页面第一行引入：

```php
require_once __DIR__ . '/sso/guard.php';
```

登录页面、扫码页面、密码校验、OIDC 令牌签发均由认证中心负责。

## 5. 人员和换届

人员主体长期保留，姓名、部门和职务不作为永久主键。每一届使用独立任职记录：先编制下一届草稿，检查差异，再指定时间原子生效。旧任职结束、新任职启用和权限版本递增在同一事务完成。

超级管理员不随普通届次自动暂停。正常换届不建议停用所有账号，否则会同时中断仍需工作的人员。

## 6. 当前管理能力

已实现：

- 密码登录和失败锁定；
- 企业微信扫码流程；
- OIDC/PKCE 和 ES256；
- SSO 与动态应用准入；
- 人员、届次、任职和原子发布模型；
- 应用登记、超级管理员初始化和届次发布 CLI；
- PHP 7.4 SDK；
- 审计基础数据结构与自动化测试。

尚未实现：

- 网页管理后台；
- 首次登录强制改密页面；
- 人员 Excel/CSV 批量导入；
- 换届差异预览和网页审批；
- 面向管理员的审计查询页面。

生产数据库目前为空，在建立首个超级管理员和应用之前不能完成真实业务登录。

## 7. 部署隔离

114 只新增 `/enterprise-sso/` 精确子路径 include 和 127.0.0.1:13000 隧道；118 认证服务只监听 127.0.0.1:3000。其他业务路径、监听端口和 HTTPS 策略不变。

系统明确禁止 HSTS，因为同一 IP 仍有其他 HTTP 程序。普通访问只使用校园网可达的 IP 80；既有域名 HTTPS 仅承接企业微信手机回调。

## 8. 数据库决定

当前使用 SQLite WAL，适合单认证节点和当前企业规模。118 原 MariaDB 5.5 承载多套旧业务、有持续外部连接和历史表损坏记录，不能为了本系统直接升级或复用。未来若出现多节点、高并发写入或数据库高可用需求，应建设独立的新数据库实例，不替换旧 MariaDB。

## 9. 更新和 GitHub

GitHub 是唯一源码基线。以后所有更新必须先修改仓库、更新手册、运行测试、提交并推送，再从明确的 commit/tag 发布。生产服务器不得存在长期未回推的手工修改。

每次生产发布必须：

1. 备份当前 release、环境变量和数据库；
2. 建立新的 release 目录；
3. 原子切换 `current`；
4. 只重启本项目服务；
5. 验证健康检查、Discovery、真实登录和应用禁用；
6. 记录生产对应的 commit/tag 和回滚点。
